# Jetson 交叉编译 SDK 构建系统 — 开发者文档

> 本文档面向**修改本仓库代码的开发者**。SDK 用户请看 `templates/usage-guide.md`
> （构建成功后会自动拷贝到 SDK 内的 `使用说明.md`）。

---

## 2. 添加新平台

把新平台接入 `jetson-cross` 的工作流：

1. 在 `lib/host-detect.sh` 的 `default_platform()` 里加新分支。
2. 如果新平台与现有 `mode` 映射不同，改 `default_mode_for_platform()`。
3. 在 `jetson-cross` 的 `case $ACTION in build) case $OPT_PLATFORM in ... esac` 里加上
   `build_<platform>()` 实现。
4. 如需新增模板，把模板放进 `templates/`，并在 `lib/docs.sh` 或 `lib/sdk-skeleton.sh` 中
   加渲染函数。
5. 在 `tests/` 下加测试，覆盖 CLI 分派、平台检测、模板渲染。

---

## 3. 添加新 JetPack 版本

`lib/jetson-versions.sh` 的 `resolve_jetson_version()` 是单一事实来源：

```bash
6.3) JETPACK_VERSION=6.3; L4T_VERSION=36.5.3 ;;
36.5.3) JETPACK_VERSION=6.3; L4T_VERSION=36.5.3 ;;
```

每个新版本都要同时给出 JetPack 与 L4T 两个方向的别名。`tests/version-resolution.test.sh`
会自动校验每个表项。

---

## 4. 模板替换语法

所有 `.tmpl` 文件使用 `@TOKEN@` 占位符，由 `lib/sdk-skeleton.sh` 的
`generate_activate_sh()`、`generate_toolchain_cmake()`、`generate_nvcc_wrapper()`
等函数用 `sed` 完成替换。需要转义 `/`、`&`、`\` 时由 `lib/sdk-skeleton.sh` 的
`escape_for_sed()` 处理。

> 不要在模板里写绝对路径——SDK 整体必须可移动。

## 5. 构建流程钩子

`jetson-cross build` 的执行顺序（节选自 `jetson-cross` 的 `build_*` 函数）：

```
build_offline_linux():
  init_sudo
  detect_os_release
  install_host_prereqs_offline
  enable_binfmt_aarch64          # 仅 x86_64
  download_bsp_and_rootfs
  extract_bsp_and_rootfs         # apply_binaries.sh 在这里跑
  mount_chroot_filesystems       # 仅构建期间
  resolve_cuda_suffix_in_rootfs
  add_jetson_apt_source_rootfs
  install_rootfs_dev_stack       # 仅按包名，不钉版本
  unmount_chroot_filesystems
  normalize_sysroot_symlinks     # 改写绝对符号链接
  toolchain_for_target           # 选择 Bootlin / 原生 GCC
  download_bootlin_toolchain     # 仅 x86_64
  locate_host_nvcc / install_host_nvcc
  build_cuda_host_include_symlinks
  generate_nvcc_wrapper
  probe_cudnn                    # 找到 cudnn.h / libcudnn.so 的位置
  pkg_config_smoke_test          # 探测 opencv4 / gstreamer / libavformat
  generate_activate_sh           # 模板 -> $sdk/activate.sh
  generate_toolchain_cmake       # 模板 -> $sdk/toolchain.cmake
  copy_example_project
  run_offline_smoke_tests        # 4 个自检产物
  slim_sdk                       # 清理下载缓存、文档等
  ship_usage_guide               # 拷贝 templates/usage-guide.md
  package_sdk                    # 仅 --no-package 关闭时
```

每一步都是 `lib/` 下的小函数，可独立单元测试。

## 6. 修复 nvcc 包装器历史 bug

旧 `setup-jetson-cross-sdk-offline.sh` 第 582–584 行有未闭合 `fi` 与死代码 `exec`，
导致每个 SDK 生成的 `bin/nvcc` 解析失败。修复后的版本在 `templates/nvcc-wrapper.sh.tmpl`：
单一 `exec`、单一闭包、所有路径由 `$cuda_version` 派生而非硬编码 `12.6`。

测试 `tests/sdk-skeleton.test.sh` 用 `grep -cE '^[[:space:]]*(if|fi)'` 验证 if/fi 配对。

## 7. 调试小技巧

jetson-cross usage-guide --out=/tmp/使用说明.md

## 8. 迁移到新仓库结构

如果你手上有旧的 SDK 目录（来自 `setup-jetson-cross-sdk-offline.sh`），
结构与新流程一致（`activate.sh` / `toolchain.cmake` / `使用说明.md` / `bin/nvcc`
/ 自检产物都在）。新流程的差异：

- **没有 JetPack 钉版本**：旧 SDK 里 `/etc/apt/preferences.d/` 或类似文件可能不存在；
  这是有意的——Jetson 仓库按 L4T 版本自动给出对应的包版本。
- **`bin/nvcc` 不再有语法错误**：旧 SDK 里的 `bin/nvcc` 是坏的，新流程下重新构建即可。
- **示例工程位置相同**：仍然是 `example-cuda-smoke/`。

无需迁移工具——重新跑 `jetson-cross build` 即可。

## 9. 已知限制

- ❌ **JetPack 7 / L4T 38 不支持**——`lib/host-detect.sh` 的 `bootlin_toolchain_for_l4t`
  只覆盖 35 / 36。L4T 38 需要新的 Bootlin release 与 host 工具链升级。
- ❌ **macOS 不支持 native 构建**——Apple Silicon 上 chroot / binfmt 不可用，必须 Docker。
- ❌ **macOS Docker 镜像体积较大**——离线 BSP + rootfs 加上 nvidia-jetpack-dev
  装出来的 sysroot 约 17 GB，zstd 压缩后约 5.8 GB。

## 10. 测试约定

每个测试文件必须是 `set -euo pipefail`，并通过 `trap 'rm -rf "$tmp"' EXIT`
清理临时目录。测试文件 **不应 grep 源码**——`tests/` 用的是行为契约（调用模块
函数并断言输出），而不是源码 grep。

新增模块时同步新增 `tests/<module>.test.sh`。
